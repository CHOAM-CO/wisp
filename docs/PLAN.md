# MR 시선 중심 관심도 기반 컴패니언 에이전트 기획서

## 1. 프로젝트 개요

패스스루(Mixed Reality) 공간에 상주하며 그래픽적으로 자연스럽게 상호작용하는 **가상 실물형 에이전트(Virtual Presence Companion)**를 구현하고, 별도의 안구 추적(Eye Tracking) 하드웨어 없이도 **사용자가 무의식적으로 시야 중심에 두는 사물들을 포착·기억하여 대화 소재와 맞춤형 추천으로 연결하는 시각 인지 메모리 파이프라인**을 구축한다.

- **타깃 디바이스**: Meta Quest 3 (Horizon OS Seamless Multitasking 환경, 향후 경량 AR 글라스 폼팩터 확장 전제)
- **엔진 / 런타임**: Godot 4.7.2 + `godot_openxr_vendors` 5.1.0-stable (OpenXR Alpha-Blend Passthrough, Boundaryless MR, Hand Tracking)

---

## 2. 핵심 제품 가설: 안구 추적 없는 시선·관심도 추정

보급형 AR 글라스나 Meta Quest 3에는 적외선 안구 추적 센서가 탑재되어 있지 않다. 본 프로젝트는 하드웨어 한계를 우회하기 위해 다음의 인간 행동 특성을 역이용한다.

1. **"사람은 관심 있는 대상을 결국 시야의 중심(Head-Gaze Center)으로 가져온다."**
2. **착용 숙련도에 따른 무의식적 정렬 강화**: 사용자가 AR 글라스나 MR 헤드셋 시야에 익숙해질수록, 눈동자만 끝으로 굴려 보기보다 무의식적으로 고개를 살짝 돌려 관심 대상을 시야 정중앙(편안한 초점 영역)에 두는 행동 패턴이 더욱 뚜렷해진다.

따라서 전체 프레임을 무차별 저장·분석하는 대신, **시야에 진입한 물체가 중심부로 얼마나 빠르게 들어오는지와 중심부에 얼마나 오래 머무는지**를 추적하면 저비용으로도 사용자의 실질적 관심 대상을 높은 정밀도로 추려낼 수 있다.

## 3. 단계별 핵심 구성요소

### 3.1. 1차 목표: 그래픽 상호작용 에이전트 가상 실물 (Virtual Presence)

- **공간 상주형 실체**: 패스스루 현실 공간 한편에 떠 있는 시각적 에이전트 실물(프로토타입: 반투명 발광 연기 정령).
- **간결하고 직관적인 그래픽 상호작용**:
  - 사용자의 시선(카메라 위치)을 부드럽게 마주 보며 호흡하듯 부유.
  - **컨트롤러(핸드 기기) 의존 없는 이중 손 인식(Dual Hand Recognition)**:
    1. **OpenXR 26관절 맨손 핸드트래킹(`XRHandTracker` + `/interaction_profiles/ext/hand_interaction_ext`)**: 컨트롤러를 내려놓은 맨손 상태에서 손바닥·다섯 손가락 끝을 60Hz로 추적해 정령 터치 물리 반응, 검지 공간 버튼 터치(정령 하단 `A/B/X/Y` 소형 룬 및 추천 카드 버튼), 엄지·검지 핀치 질문 트리거를 모두 수행.
    2. **RGB 패스스루 카메라 기반 손 인식(`MediaPipe HandLandmarker` 21-Keypoint)**: 전용 적외선 핸드트래킹 기기나 컨트롤러가 전혀 없는 경량 AR 글라스/단일 RGB 카메라 환경까지 고려하여, 전면 카메라 영상만으로 손 관절과 핀치 제스처를 실시간 검출해 3D 공간 입력으로 투영.
  - 에이전트 상태(관심 물체 포착, 백그라운드 공존, 검색·발화 준비 등)를 과한 UI 창 대신 실물의 색온도·맥동·짧은 말풍선으로 전달.
  - Horizon OS `session_visible` 상태에서도 멈추지 않고 동작해 2D 창 앱들과 동시 공존.

### 3.2. 시각 인지 및 계층형 메모리 파이프라인 (Sensory → Mid-Term → Long-Term)

```
[패스스루 카메라 프레임]
       │  (Quest 3 Passthrough Camera API / Android Camera2)
       ▼
[1. 실시간 객체 탐지 & 다중 객체 추적 (Object Detection + MOT)]
   - 시야 내 물체 Track ID 부여 및 객체 크롭 이미지 임시 캐싱 (Sensory Buffer)
       │
       ▼
[2. 시야 중심 기반 관심도 점수 산정 (Center-Gaze Interest Scoring)]
   - 지표 A: 시야 포착 후 중심 영역(Center ROI) 진입까지 걸린 시간 (Time-to-Center)
   - 지표 B: 중심 영역 내 누적/연속 체류 시간 (Center Dwell Time)
   - 지표 C: 중심점 근접도 가중치 및 재진입 횟수
       │
       ├── 임계 점수 미달 ──▶ 즉시 폐기 (임시 캡처 및 추적 버퍼 삭제)
       │
       ▼ 임계 점수 이상
[3. 중단기 메모리 (Mid-Term Memory) 승격 & 인덱싱]
   - 저가(경량) VLM 모델로 객체 크롭에 대한 텍스트 어노테이션 생성
   - EmbeddingGemma 2로 임베딩 생성 후 (벡터 + 텍스트 어노테이션 + 캡처 + 점수 메타데이터) 저장
       │
       ├── 미사용 시 자연 감쇠 / 정리
       │
       ▼ 실제 검색(Retrieval)에 사용됨
[4. 장기 메모리 (Long-Term Memory) 승격]
   - 대화 맥락이나 상품 추천 검색에서 실제로 호출·활용된 항목만 영구 관심 기억으로 승격
```

#### (1) 감각 캐시 (Sensory Buffer)
- Quest 3 전면 RGB 패스스루 카메라(`horizonos.permission.HEADSET_CAMERA` / Godot `CameraServer` 피드)에서 경량 객체 탐지 및 추적을 수행한다.
- 시야에 들어온 각 객체(`track_id`)의 가장 선명한 중심 근접 크롭 캡처를 메모리에 임시 보관한다.

#### (2) 관심도 점수(Interest Score) 산정 기준
각 추적 객체 $i$에 대해 시야 이탈 시점 또는 일정 관측 윈도우마다 관심도 점수 $S_i$를 계산한다.

- **중심 진입 속도 ($\Delta t_{\text{to\_center}}$)**: 객체가 시야 외곽에서 최초 탐지된 시각 $t_{\text{first}}$부터 시야 중심 반경(Center ROI, 예: 정규화 화면 반경 $r \le 0.22$)에 최초 진입한 시각 $t_{\text{center}}$까지의 시간 차. 짧을수록 의도적으로 고개를 돌려 포착한 강한 주의 신호로 높은 점수를 부여한다.
- **중심 체류 시간 ($T_{\text{dwell}}$)**: 객체 중심이 Center ROI 내부에 머문 총 시간(연속 체류 시 가산점). 스쳐 지나간 배경 사물(고개 회전 중 통과)을 걸러내는 핵심 필터 역할을 한다.
- **중심 근접도 가중치**: 프레임 내 화면 정중앙 $(0.5, 0.5)$와의 거리에 반비례하는 가중 평균을 반영한다.
- **판정**: $S_i < \theta_{\text{interest}}$ 인 객체는 시야 이탈 즉시 캡처와 함께 메모리에서 제거하고, $S_i \ge \theta_{\text{interest}}$ 인 객체만 중단기 메모리 큐로 넘긴다.

#### (3) 중단기 메모리(Mid-Term Memory) 저장 및 인덱싱
- **저가 모델 텍스트 어노테이션**: 중단기 메모리 진입 시점에만 저비용 경량 멀티모달 모델(저가 VLM)을 비동기 호출하여, 캡처된 물체의 구체적 텍스트 어노테이션(품목명, 색상·형태·소재 등 시각 속성, 추정 용도/카테고리, 주변 상황 키워드)을 생성한다. (모든 프레임에 VLM을 돌리지 않고 관심 임계치를 넘긴 객체에만 호출하여 비용과 지연을 최소화한다.)
- **EmbeddingGemma 2 기반 인덱싱**:
  - Google DeepMind의 오픈웨이트 멀티모달 임베딩 모델인 **EmbeddingGemma 2**(768차원 통합 벡터 공간, Matryoshka 차원 축소 지원)를 사용해 인덱싱한다.
  - 저장 레코드 구성: `임베딩 벡터` + `텍스트 어노테이션` + `캐싱된 객체 캡처 경로` + `관심도 메타데이터(최초 포착 시각, 중심 진입 소요 시간, 중심 체류 시간, 관심도 점수)`.

#### (4) 장기 메모리(Long-Term Memory) 승격 조건
- 중단기 메모리에 올라온 모든 관심 후보가 영구 저장되지는 않는다.
- 이후 사용자의 질문이나 에이전트의 대화·추천 과정에서 **실제로 검색(Retrieval)되어 결과로 채택·활용된 항목만 장기 메모리로 승격**한다.
- 이를 통해 일시적 호기심과 실제 반복·지속 관심사를 구분하고 장기 메모리의 신호 대 잡음비(SNR)를 높게 유지한다.

## 4. 검색(Retrieval) 아키텍처

기억 저장소(중단기 + 장기 메모리) 조회 시 의미적 유사성과 정확한 단어 일치를 모두 놓치지 않도록 **두 가지 검색 경로 결과를 각각 상위 3개씩 반환**한다.

1. **벡터 서치 (Vector Search — 상위 3개 반환)**
   - 질의(또는 현재 보고 있는 장면/대화 맥락)를 EmbeddingGemma 2 벡터로 변환해 코사인 유사도 기준 **상위 3개(Top-3)** 기억 반환.
   - 정확한 단어가 달라도 분위기·카테고리·시각적 유사성이 연결되는 항목 포착.
2. **단어 기준 검색 (Lexical / Keyword Search — 상위 3개 반환)**
   - 저장된 텍스트 어노테이션에 대해 형태소/토큰 기반 전문 검색(SQLite FTS5 / BM25 등)을 수행해 **상위 3개(Top-3)** 기억 반환.
   - 브랜드명, 특정 색상·재질, 고유 명사 등 정확한 키워드 매칭 보장.

에이전트 응답 생성기는 이 두 경로의 결과(각 최대 3개)를 컨텍스트로 받아 대화 응답이나 추천을 구성하며, 이때 실제로 인용·활용된 중단기 기억은 장기 메모리로 승격 처리한다.

## 5. 대화 확장 및 상품 추천 UX 원칙

### 5.1. 관심사 기반 일상 대화(Small Talk & Context Talk)
- 사용자가 무엇을 유심히 봤는지 시선 중심 메모리가 쌓여 있으므로, 막연한 범용 챗봇과 달리 **"방금 꽤 오래 보던 머그컵, 평소 쓰던 거랑 비슷한 톤이네"**, **"요즘 우드 톤 소품 쪽에 자꾸 눈이 가는 것 같아"**처럼 사용자의 실제 시선 맥락에 뿌리를 둔 자연스러운 대화가 가능해진다.

### 5.2. 쇼핑 / 상품 추천 제시 규칙: **딱 2가지 예시만 제시**
- AR/MR 시야 안에서 긴 상품 목록을 띄우면 시야를 가리고 피로도가 급격히 올라간다.
- 상품 추천을 수행할 때는 수집된 관심 속성(어노테이션 + 메모리 검색 결과)을 바탕으로 **가장 적합한 대조군 또는 베스트 후보 딱 2가지 예시만 간결하게 제시**한다 (예: 디자인/감성 중심 후보 1개 + 가성비/실용 중심 후보 1개).

## 6. 사용자 설정 구성 및 데모 전용 설계 원칙

### 6.1. 해커톤 데모용 사용자 설정 (2가지 모드)
시연 환경에서 에이전트의 개입 방식을 직관적으로 비교·검증할 수 있도록 다음 2가지 모드를 설정으로 준비한다.

1. **항상 추천, 바로바로 추천 (Immediate / Always-On Proactive Mode)**
   - 관심도 점수가 임계치를 넘겨 새로운 관심 사물이 포착되거나 연관 추천 맥락이 형성되면, 에이전트가 사용자 발화를 기다리지 않고 즉시 말을 걸어 대화나 2가지 상품 예시를 제안한다.
2. **물어봤을 때만 검색 후 제안 (On-Demand / Pull Mode)**
   - 평소에는 시야 중심 추적과 중단기 메모리 인덱싱만 백그라운드에서 조용히 수행하고, 사용자가 에이전트에게 직접 물어보거나 추천을 요청했을 때만 하이브리드 검색(벡터 상위 3개 + 단어 상위 3개)을 실행해 답하고 제안한다.

### 6.2. 실제 프로덕트 방향성 명시 (레포지토리 문서 전용 기록)
> **설계 주석 (UI 미노출 사항)**:  
> 위 두 가지 방식(`항상 바로바로 추천` vs `물어봤을 때만 검색 후 제안`)을 사용자가 직접 고르는 설정으로 분리해 둔 것은 **순전히 해커톤 데모 시연과 동작 검증을 위한 구성**이다.  
> 실제 지향하는 프로덕트에서는 이를 사용자 설정 토글로 두지 않는다. 실제 제품에서는 설정 메뉴 없이 에이전트가 사용자의 현재 몰입 상태, 시선 체류 강도, 주변 상황, 이전 대화 수용도를 종합해 스스로 말 걸 타이밍과 침묵할 타이밍을 적응적으로 결정한다. 이 원칙은 데모 앱 UI 문구에는 노출하지 않고 본 레포지토리 문서에만 명시한다.

## 7. 데모 시각화 렌더링 모드 & 컨트롤러 버튼 매핑 (X-Ray Debug Toggle)

### 7.1. 설계 배경
실제 사용 환경에서는 객체 탐지 바운딩 박스, 시야 중심 반경(Center ROI), 실시간 관심도 점수, 백그라운드 어노테이션 및 검색 과정이 사용자 눈에 보이지 않아야 시야가 쾌적하다.  
하지만 **해커톤 현장 시연 및 제출용 녹화 영상**에서는 내부 파이프라인이 실시간으로 작동하고 있음을 직관적으로 증명해야 하므로, **Quest Touch Plus 컨트롤러 조이스틱 옆 버튼들(`A`, `B`, `X`, `Y`)로 평소엔 숨겨진 내부 동작 레이어들을 즉시 토글**할 수 있게 구성한다.

### 7.2. 컨트롤러 조이스틱 옆 버튼 매핑 규격
Godot `openxr_action_map.tres`의 `/interaction_profiles/oculus/touch_controller` 액션(`ax_button`, `by_button`)에 다음과 같이 매핑한다. 기본값은 모든 디버그 오버레이 **OFF(실사용 클린 뷰)** 상태로 시작한다.

| 컨트롤러 위치 | 버튼 (OpenXR 액션) | 토글 / 동작 기능 | 실사용 기본값 및 시연 시 화면 연출 |
| :--- | :--- | :--- | :--- |
| **오른손 조이스틱 옆 하단** | **`A` 버튼** (`RightHand` `ax_button`) | **객체 탐지 BBox & 시선 중심 관심도 렌더링 토글** | **기본 OFF**. ON 전환 시 패스스루 시야 위에 ① 중앙 관심 영역(Center ROI 가이드 링), ② 실시간 객체 탐지 **Bounding Box + Track ID**, ③ 객체별 **중심 진입 시간($\Delta t$) · 체류 시간($T_{\text{dwell}}$) · 관심도 게이지**를 오버레이 렌더링. 임계 점수 돌파 순간 박스 하이라이트 및 캡처 연출 표시. |
| **오른손 조이스틱 옆 상단** | **`B` 버튼** (`RightHand` `by_button`) | **메모리 승격 & 하이브리드 검색 X-Ray 패널 토글** | **기본 OFF**. ON 전환 시 공간 한편에 반투명 인스펙터 카드를 띄워 ① 중단기 메모리 진입 캡처 썸네일 + **저가 모델 텍스트 어노테이션** + **EmbeddingGemma 2 인덱싱 상태**, ② 검색 시 **벡터 서치 상위 3개** vs **단어 기준 검색 상위 3개** 실시간 비교 결과, ③ **중단기 → 장기 메모리 승격(Promoted)** 배지를 시각화. |
| **왼손 조이스틱 옆 하단** | **`X` 버튼** (`LeftHand` `ax_button`) | **데모 추천 개입 모드 전환 토글** | 별도 설정 메뉴를 열지 않고 시연 중 원버튼으로 **`모드 1: 항상 바로바로 추천`** ↔ **`모드 2: 물어봤을 때만 검색 후 제안`** 즉시 전환 (전환 시 1.5초간 짧은 상태 토스트만 표시 후 소멸). |
| **왼손 조이스틱 옆 상단** | **`Y` 버튼** (`LeftHand` `by_button`) | **질문 / 추천 요청 수동 트리거 (Push-to-Talk)** | 시끄러운 해커톤 시연장 소음 환경에서 오작동 없이 음성 질의 구간을 끊어 보내거나, 모드 2(물어봤을 때만 제안) 시연 시 검색 + **상품 추천 2가지 예시 카드** 호출을 확실하게 트리거. (길게 누르면 데모 세션/에이전트 위치 리셋 보조 기능 배정 가능) |

### 7.3. 패스스루 위 바운딩 박스 투영 및 녹화 호환 설계
- Quest 3의 시스템 내장 녹화 및 공식 캐스팅은 패스스루 배경 위에 **OpenXR 알파 블렌드 뷰포트에 렌더링된 3D 요소들**을 합성(Compositing)하여 저장한다.
- 따라서 `A` 버튼으로 켜는 바운딩 박스와 Center ROI는 단순 2D 카메라 버퍼 위가 아니라, `Camera2` 내부 파라미터(`LENS_INTRINSIC_CALIBRATION`)와 헤드셋 기준 카메라 포즈(`LENS_POSE_TRANSLATION` / `ROTATION`)를 이용해 **`XRCamera3D` 전방 기준 평면에 정렬된 3D 공간 오버레이 레이어(`DebugVisionOverlay` 노드)**로 렌더링한다.
- 이렇게 구성하면 평소(`visible = false`)에는 렌더링 비용이 0이고, 시연 중 `A` 버튼을 누르는 즉시 현실 사물 위에 바운딩 박스와 관심도 점수가 겹쳐 보이며 **퀘스트 자체 녹화 영상에도 그대로 선명하게 기록**된다.

> **데모 매핑 관련 레포지토리 주석**:  
> 위의 바운딩 박스 오버레이(`A`), 메모리·검색 X-Ray 패널(`B`), 개입 모드 수동 전환(`X`) 역시 해커톤 시연에서 내부 알고리즘 동작을 투명하게 보여주기 위한 **데모 전용 시각화 장치**이며, 일반 소비자용 실사용 화면에서는 비노출 상태가 표준이다.
